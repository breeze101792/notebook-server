Table editing in hybrid mode

Design mockup — dark and light themes. Grips, drop indicators and the drag state are drawn statically here; in the app they appear on hover or focus. Colored tokens only: --bg --bg-panel --bg-elev --fg --fg-muted --accent --accent-soft --border --danger --warn.

Dark theme hover / focus reveal

The table on the left is in the resting state. The table on the right is shown as if the pointer were over it: a disabled grip sits beside the pinned header row, live grips beside each body row, and a column grip above each header cell.

Drag in progress static simulation

Row drag: the source row is drawn as a translucent ghost in the overlay, a proxy chip follows the pointer, and a horizontal drop line marks the insertion boundary. Nothing is added to the table DOM. The same pattern applies to a column drag, with a vertical drop line.

Edge cases disabled states

The header row is pinned: its grip is shown but disabled, because a Markdown table's first row must stay all-<th> or turndown saves the whole table as raw HTML. A table with merged cells disables reordering entirely rather than silently normalising.

Context-menu fallback keyboard + touch

The existing Table submenu gains the four Move commands at the top and keeps every insert/delete command. This is the canonical keyboard path: the menu takes focus on open and ↑/↓/Enter/Escape navigate it. Chords are shown for the new commands only.

Column width resize is intentionally absent. Markdown cannot store a width, so a resize control would silently reset on the next load. Column alignment round-trips (:-- / :-: / --:) and is offered instead.
