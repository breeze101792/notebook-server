The Edit table window, codified

The shipped look, not a redesign. One GFM table opens in the shared edit-window shell; the grid is a real table with a sticky header, a rectangular selection, an 8 px fill handle, a TSV + HTML clipboard and an in-window history. Dark is the full set; light repeats the four states that prove the palette. Nothing here is a component outside docs/ui/table-editor.md except the frame, which is drawn for context. Annotations sit outside the boards.

editable blocked / warning history enabled Boards are 1160 px wide; scroll sideways on a narrow screen.

1 · Default — a 4-column table, cell (0,0) focused

The window opens on the header's first cell. The ring is the 2 px inset accent; the single-cell selection also places the 8 px fill handle on that cell's corner. The toolbar is one row; Move up, Move down, Insert above and Delete row are disabled because the active cell is the header.

The fill handle is part of the selection, so it is visible even on a single header cell. The grid is 4 × 4: one header row plus three body rows. Undo and Redo are disabled on a clean open.

2 · Editing a cell — the cell is the editor

The focused cell's .te-cell-text is contenteditable in place. There is no overlay, no second box, and the column does not move. The caret is accent-coloured. The fill handle stays on the corner while editing; that is shipped.

Tab commits and moves one column; Enter commits and moves down; F2 leaves text edit without moving the cell. Esc cancels the whole window, even mid-word. The typing burst is one history step.

3 · Rectangular selection and the fill handle

A 3 × 3 range, rows 2–4 and columns 1–3. The wash is translucent, so the zebra survives under it; the outer edge is 1 px of accent on each outside cell. The active cell at the bottom-right keeps the 2 px ring, and the 8 px handle rides its corner. The status line announces once, on release.

A selection is not a history step: Undo and Redo stay disabled. Shift+Arrow extends from the anchor; a bare arrow collapses the range first. Esc collapses a range before it cancels the window.

4 · Clipboard — copy leaves the range where it was

Copy writes TSV into text/plain and one HTML table into text/html. The rectangle stays selected and the active cell keeps focus. Copy is not a model change, so both history buttons remain disabled.

6 · Aligned column — right alignment, header included

The alignment button cycles the active column left → center → right. It writes the same align on every cell of the column, header included. The shipped glyph never changes; only the title and the status carry the current value.

7 · Merged cells — the blocked state

GFM cannot represent colspan or rowspan. The table still opens so the refusal is discoverable: a notice strip, every tool aria-disabled, no cell in the tab order, no ring, no selection, Apply hidden. Only Cancel closes. Focus lands on Cancel.

The grid is a padded snapshot, not a merge: the spanned cell's text occupies one cell and the row is padded with empty cells. The empty-cell dot still renders because the text span is empty. The clipboard tools name the same refusal in their title and write it to the status line when activated.

8 · Empty and one-cell tables

A header-only source table is legal; the grid shows the header and no body rows. A one-column, one-body-row table is the minimum. Add row is the way out of the header-only state; Delete row and Delete column are disabled at the minimum.

The bar scrolls behind its right-edge mask in both small windows. A sort needs two body rows; both selects are disabled and both direction toggles are aria-disabled. Add row appends the first body row.

9 · Apply — there is no applying state

Apply is synchronous. The table is replaced, the note is marked dirty and the write is scheduled, the window hides and focus lands in the note — all in the same task. No spinner, no aria-busy, no disabled Apply, no “Applying…” label. This board is the last frame before the window disappears.

10 · Error — one plain line in the status region

The only in-window failure is a history restore that cannot run. It is written as ordinary status text: same size, same muted colour, no icon, no role="alert". That is shipped; a proposal in §12 would give failures a different tone.
