Sessions page — §sessions

Static reference for sessions-page.md. Every board is drawn in both themes (dark first, light under it), so the file needs no script and no toggle. The page rules are the doc’s §12.2 verbatim; only the frames, captions, notes and geometry labels are mockup chrome. Every page-alone board is drawn at the width 1280 leaves the page, not at the viewport: 740 is 1280 with both panels open, 960 is 1280 with the outline collapsed. The data is four sessions holding seven tab entries — Work (4: the current session, with a dirty tab and two special tabs), Reading (2, one of them changed on disk), Bench tests (1) and Archive (0, the empty card that exists to be a drop target). Board 1 shows the page in the shell, where the same four cards now wrap to two columns.

Drag in flight, two tabs carried, page 740 wide. Both carried rows dim to --opacity-drag, one in Work and one in Bench tests, because the carried set is the selection and the selection spans cards. Reading is the target: 1 px accent border, 1 px inset accent ring, and its count text replaced by Move here in --accent at 600 — the count element keeps data-count-text="2 tabs" so dragend can restore it. The gesture is pointer-only by design; the row menu is the keyboard and touch path (§8 of the doc).

The differences are behavioural and textual only: every wrapper is draggable="false" and no row carries .is-dragging or .is-drop-target, dragover is never prevented, the row menu’s Move to session is disabled with Read-only: sessions can’t be changed., and the footer drops its drag sentence, leaving Pinned tabs are shared and are not listed here.

Reference only. The normative text is sessions-page.md; where this page and the doc differ, the doc wins. No network request, no web font, no script: both themes are drawn, so the file opens offline and renders identically. The host carries the id #sessions-page once per board in the app; here each board carries the classes only, because one document cannot hold twelve ids. The boards are 1:1 at the width the editor leaves the page, not at a viewport — the shell board alone is scaled.
