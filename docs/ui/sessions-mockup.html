Sessions — side-panel view

Firefox-style tab groups, one named set of unpinned tabs per task, with the workspace's pinned tabs shared by every session. The control is the Sessions view beside Explorer, Pinned and Bookmarks. The tab bar is untouched.

2 · The rows — 240 px, 360 px, and the row menu

One row per session: name, unpinned count, an 8 px dot when that session has unsaved work, and a per-row ⋯ that opens Rename / Delete. The active session is fill + a 2 px accent edge + weight, not colour alone. The name is the only flexible child; the count, dot and ⋯ never shrink.

9 · Phone — the view does not exist

The phone shell has one reader, no tab bar, and never reads or writes desktop sessions. The Sessions rail icon and its host are hidden by the same phone rule that hides the AI view; a saved activeView: "sessions" falls back to Explorer.

Bottom rail — Sessions omitted

The rule

@media (max-width: 860px), ((pointer: coarse) and (max-width: 1023px)) {
  .activity-btn[data-view="sessions"],
  #side-panel .side-panel-view[data-view="sessions"] { display: none; }
}

The view is still built at load on a phone — it is a hidden DOM subtree and keeps sessions.js free of a mode branch. Nothing else on the phone changes.
