Session — create, and the delete confirm

40 characters after trimming, 20 sessions per workspace. The delete is a native confirm: no styling, no markup, no focus contract of ours.

Session — create420 px · label column 92shipped · E1

New session

A session is a named set of open tabs. Pinned tabs stay in every session.

Session — delete confirmnative browser chrome, not oursunstyled

127.0.0.1:5000

Delete “Deep work”? Its 3 open tabs will close. You’ll switch to “Reading”. Unsaved edits in its files will be lost.

  • The confirm is composed, not fixed: the tab sentence changes with the count, the “You’ll switch to …” clause appears only when the active session has a neighbour, and the unsaved line appears only when a file in that session is dirty.
  • The dialog never disables submit for content. Validation runs on submit and every open resets the button, so a past failed submit cannot leave the next one dead.
  • Pinned tabs are words here, not the 📌 glyph — that glyph lives in the Sessions panel footnote, which is out of scope.

Toast — the only other feedback surface

One node, one sentence, no action, 1.5 s. It never takes focus and never blocks the pointer under it.

  • A toast is never the answer to a failure inside a dialog. That failure goes in the dialog's own error slot, on the field that owns it, and the dialog stays open.
  • Nothing destructive lives in a toast. The three destructive decisions are native confirms with the copy in §6.4.
